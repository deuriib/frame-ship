# Verifying People Decisions Before Release

## Overview

**Core principle:** Evidence before announcements, always.

**Violating the letter of this rule is violating the spirit of this rule.**

A people decision communicated wrong travels faster than the correction ever will. Verify the decision, the message, and the paperwork - then release.

## The Iron Law

```
NO PEOPLE COMMUNICATION WITHOUT FRESH VERIFICATION EVIDENCE
```

If you haven't re-read the decision package, the message draft, and the recipient list in this pass, you cannot send it.

## The Gate Function

```
BEFORE any offer, rating, PIP, promotion, reorg, policy, or exit message leaves your hands:

1. IDENTIFY: What proves this decision is right and ready? (evidence + approvals + draft)
2. RUN: Read the FULL decision package (fresh, complete) - not your memory of it
3. READ: Evidence, consistency, wording, recipients, timing, paperwork - all of it
4. VERIFY: Does everything confirm the claim?
   - If NO: State actual status with evidence
   - If YES: Release WITH the evidence reference
5. ONLY THEN: Communicate

Skip any step = announcing, not verifying
```

## Common Failures

| Decision | Requires | Not Sufficient |
|----------|----------|----------------|
| Offer sent | Scorecard coverage + approvals + comp sign-off | Verbal yes, "should be fine" |
| Rating communicated | Evidence log + calibration note | Manager confidence |
| PIP started | Prior feedback record + measurable bar + support | Frustration, "they know" |
| Promotion announced | Next-level evidence + need + calibration | Tenure, retention panic |
| Reorg announced | Diagnosis + design + comms + support plan | Leadership alignment alone |
| Exit executed | Paperwork + logistics + message + dignity check | "Legal said ok" alone |
| Policy published | Rationale + impact + FAQ + effective date | Good intentions |

## Red Flags - STOP

- Using "should", "probably", "seems fair"
- Expressing satisfaction before verification ("Great hire!", "Done!", etc.)
- About to send/announce without re-reading the package
- Trusting memory of the decision ("we already agreed")
- Relying on partial checks ("comp is basically approved")
- Thinking "just this once, send it"
- Tired and wanting the conversation over
- **ANY wording implying readiness without having re-read the package**

## Rationalization Prevention

| Excuse | Reality |
|--------|---------|
| "Should be ready now" | READ the package |
| "I'm confident" | Confidence ≠ evidence |
| "Just this once" | No exceptions on people decisions |
| "HR already saw it" | HR review ≠ your verification |
| "The leader approved" | Approval ≠ accuracy of what you're sending |
| "I'm tired" | Exhaustion ≠ excuse |
| "Partial check is enough" | Partial proves nothing |
| "Different words so rule doesn't apply" | Spirit over letter |

## Key Patterns

**Offers:**
```
✅ [Read scorecard + approvals + letter] [See: coverage full, band signed] "Offer ready to send"
❌ "Should be fine to send" / "Looks right"
```

**Ratings / PIPs / promotions:**
```
✅ [Read evidence + calibration + draft message] [See: consistent] "Ready to deliver"
❌ "We've discussed it enough"
```

**Reorgs / exits:**
```
✅ [Read diagnosis + design + comms + recipient list + logistics] [See: all green] "Ready to announce"
❌ "Leadership aligned, let's go"
```

**Paperwork:**
```
✅ Re-read letter → Check names, numbers, dates → Confirm signatories → Release
❌ "Template is standard, skip the re-read"
```

## When To Apply

**ALWAYS before:**
- ANY offer, rating, PIP, promotion, or comp message
- ANY reorg, policy, or program announcement
- ANY exit conversation or letter
- ANY message about a person that leaves your hands in writing
- Moving to the next people task
- Closing a hiring or review cycle

**Rule applies to:**
- Exact phrases
- Paraphrases and synonyms
- Implications of readiness
- ANY communication suggesting a people decision is final
