# Financial Verification — Evidencia Antes que Declaraciones

**Core principle:** Evidence before claims, always. Violar la letra es violar el espíritu.

## The Iron Law

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

Si no corriste la verificación en este mensaje, no puedes declararla pasada.

## The Gate Function

```
ANTES de declarar cualquier estado o mostrar satisfacción:

1. IDENTIFY: ¿Qué check prueba esta declaración?
2. RUN: Ejecuta el check COMPLETO (fresco, completo)
3. READ: Salida completa, cuenta desvíos, lee cada cifra
4. VERIFY: ¿La salida confirma la declaración?
   - Si NO: declara el estado real con evidencia
   - Si SÍ: declara CON evidencia
5. SOLO ENTONCES: haz la declaración

Saltar un paso = mentir, no verificar
```

## Common Failures

| Claim | Requires | Not Sufficient |
|-------|----------|----------------|
| Checks pasan | Salida del check: 0 en rojo | Corrida previa, "debería pasar" |
| Concilia | Conciliación: diferencia explicada o cero | "Se ve bien", extrapolación |
| Balance cuadra | A = P + E verificado en esta sesión | El P&L cierra, "se ve bien" |
| Caja cierra | Flujo reconciliado contra bancos | Utilidad positiva |
| Desvío corregido | Caso congelado hoy cuadra | Celda cambiada, asumido |
| Regresión cubierta | Check nuevo en verde que lo atraparía | Pasa una vez |
| Anomalía revisada | Duplicados, redondos, vendors raros, off-hours chequeados | "Se ve normal" |
| Requisitos cumplidos | Checklist del brief línea por línea | Checks pasando |

## Red Flags - STOP

- Usar "debería", "probablemente", "parece"
- Mostrar satisfacción antes de verificar ("¡Listo!", "¡Perfecto!")
- Enviar/declarar/firmar sin verificación
- Confiar en reportes de éxito sin evidencia
- Verificación parcial
- Pensar "solo esta vez"
- Cansado y queriendo terminar
- **CUALQUIER declaración sin evidencia fresca en este mensaje**
