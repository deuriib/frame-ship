# Go To Market

## Overview

A launch is a bet with a date. Positioning first, channels second, checklist always.

**Announce at start:** "I'm using the go-to-market skill to plan this launch."

## Positioning (before anything else)

One paragraph, five lines:

1. **For** [segment] **who** [struggle with job]...
2. **Our** [product/bet] **is a** [category]...
3. **That** [core outcome]...
4. **Unlike** [status quo / competitor]...
5. **We** [proof: metric, customer, evidence link]...

If line 5 has no proof, the launch waits for validating-bets. Proof-free launches are announcements, not GTM.

## Messaging Hierarchy

- **One promise** — the headline. Eight words max.
- **Three proof points** — each with a number or a name.
- **One action** — the single next step. Every asset drives to it.
- Voice check: read it aloud. If a human wouldn't say it to a peer, rewrite it.

## Channel Plan

Per channel (max 3 for launch week): owner, asset, send date, expected outcome (number + window), kill rule (below X by day Y → cut spend/effort).

- Owned (email/list) first — free and attributable.
- Borrowed (partners, communities) second — one ask per partner, make it easy to say yes.
- Paid last — only with a priced-pilot-proven message and a CAC ceiling from pricing-packaging.

## Launch Checklist

- [ ] Positioning paragraph approved by human partner
- [ ] One promise + 3 proofs + 1 action locked
- [ ] ≤3 channels, each with owner/date/expected outcome/kill rule
- [ ] Proof asset live (evidence, demo, or customer quote with permission)
- [ ] Anti-metrics dashboard linked (signup quality, support load, churn)
- [ ] Day-7 retro scheduled with owner named
- [ ] verification-before-launch gate passed before "launched" is claimed
- [ ] Sold-capability check — nothing already sold was removed or reclassified without the same customer notification as any other customer-facing change
