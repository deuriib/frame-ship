# Requesting Product Review

## Overview

Fresh eyes before launch. Request review when milestones ship, PRDs complete, or launches approach — never ship unreviewed bets on unproven demand.

**Announce at start:** "I'm using the requesting-product-review skill to get review on this work."

## When to Request

- PRD complete, before validation starts.
- Any milestone where acceptance was missed and pivoted.
- Pre-launch: after verification-before-launch passes, before public claim.
- Pricing or positioning change affecting paying users.

## How to Request

1. **Link the artifact:** PRD path, evidence files, metric outputs. Reviewers read artifacts, not summaries.
2. **State the bet in 3 lines:** job, success metric + current number, decision you want (approve / pivot / kill).
3. **Name the review focus:** the 2 riskiest spots you want pressure on. Don't ask for "general feedback" — it returns general noise.
4. **Set the window:** what blocks until review lands, and by when you need it.

## Receiving Review

- Fix first what breaks acceptance or evidence; debate second what is taste.
- Every accepted change gets a PRD/brief edit + commit, not just a chat reply.
- Rejected suggestions get a one-line why in the thread. Silence is not a decision.
